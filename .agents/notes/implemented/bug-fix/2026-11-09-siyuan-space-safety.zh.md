# Agent Note: 保持 SiYuan Space 安全与初始化正确性

Status: implemented

[English](2026-11-09-siyuan-space-safety.md) | 中文

## 问题

数据库搜索结果受限以及 SQL 索引延迟可能导致重复创建 Memories 数据库。启动器的失败处理、内核发现和本地初始化页面也需要明确的安全边界。不检查内容而直接复用同名指南会阻碍指南更新。

## 决策

刷新 SiYuan 事务队列并检查目标文档中的数据库块，不再全局搜索。保留启动器首次失败，使用环境变量传递访问码，拒绝已启用网络服务的工作区，并对自动发现的内核校验受支持的校验和。显式传入的内核路径由调用方负责验证。本地页面禁止嵌入并要求一次性初始化凭证。变更后的指南另建文档，绝不覆盖现有内容。

## 考虑过的替代方案

- 全局数据库搜索最多返回 12 条结果，不能据此确认数据库不存在。
- 替换现有指南可能丢失用户编辑；单独创建版本可以保留这些内容。
- 信任 `PATH` 上找到的所有内核会静默执行未经验证的二进制文件。

## 后果

自动发现的内核仅限已知的 macOS arm64 发行版；其他已验证安装需要设置 `SIYUAN_KERNEL`。本地凭证无法验证本身就能读取页面的进程。并发初始化和记录之外的平台尚未验证。

## 验证

- Regression — `node scripts/memories/tests/verify-review.mjs`：使用真实 SiYuan 内核验证 12 条搜索上限、重复初始化、指南保留、启动失败、页面凭证及 smoke 清理；参见[验证报告](../../../../docs/verification.md)。
